The seven jobs

Python does five of these today. Five are new.

#JobWhat it meansToday?

2Judge termsRead robots and the terms pages, propose a verdict with the quoted clausePartly — done by hand in M1

The boundary

PythonLaravel
Scraped tablesWritesReads
Live site tablesNo access at allWrites
The run queueClaims and updatesFills
JudgementProposesDecides
Enforced, not agreed

Two database roles. Python's role has no write permission on the live tables — so a bug in the scraper cannot reach the public site. It is a permission error, not a code review.

How a run works

Laravel ──INSERT runs(queued, source_ids, reason) │ Python ──claims the row ──► running ──gate.check nothing reaches the network without this ──fetch 1 req/host, 2s apart, robots honoured ──read data endpoint (JSON) or HTML pages ──hash + compare new · changed · unchanged · gone ──INSERT scraped_classes + a publish-readiness proposal ──UPDATE runs ──► done | failed(reason) │ Laravel ──reads new/changed rows ──► review ──► live tables

Re-reading a source

There is no separate refresh pipeline. A re-read is an ordinary run — the same queue, the same gate, the same politeness. Only the trigger differs.

sources.next_run_at <= now() │ Laravel scheduler ──INSERT runs(reason: 'nightly') │ Python ──conditional fetch If-None-Match / If-Modified-Since │ ├── 304 Not Modified ──► stop. nothing changed, nothing re-parsed │ └── 200 + same content_hash ──► stop. page changed cosmetically only │ └── content differs ──► re-extract ──► compare each class │ unchanged · changed · new · gone
Source kindRe-read everyWhy
Municipal catalogues30 daysTerms turn over seasonally; prices and dates move with them
Provider sites60–90 daysA gym's own page changes rarely
Before enrolment windowsTighterAugust and December. Kids' activities are seasonal, so the schedule should be too
Most re-reads should cost almost nothing

Three cheap exits before any parsing happens: a 304 ends the request entirely; an unchanged content_hash ends the extraction; and an unchanged class hash means Laravel is never told about it. Re-verification is mostly proving nothing changed — quietly, and without asking the source for more than it already gave us.

What a re-read never does

It does not overwrite a live class. Python writes a fresh row with change_status = changed and Laravel decides whether the update reaches the site. A failed or partial re-read changes nothing at all — a failed read must never overwrite good data with nothing.

Telling new from old

Every scraped class gets a content hash. The next run compares.

ComparisonStatusWhat happens
Same hash as last timeunchangedTouch last_seen_at. Nothing for Laravel to do
Hash differschangedNew row; Laravel re-judges it
Not seen beforenewNew row; Laravel judges it
Was there, now absentgoneFlagged only. Never deleted
Absence is not evidence of cancellation

A site redesign, a pagination change, or a half-failed fetch all look exactly like every class disappearing. So gone needs two consecutive clean runs, a healthy yield, and a cap: if more than a third of a source's classes would vanish at once, none are flagged and one alert is raised instead.
