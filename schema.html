-- A claim whose value is absent from its evidence cannot be stored.
-- Python already refuses to construct one; this catches the bug in Python.
CREATE FUNCTION claims_evidence_check() RETURNS trigger AS $$
BEGIN
  IF position(NEW.value in NEW.evidence) = 0 THEN
    RAISE EXCEPTION 'claim value % is not present in its evidence', NEW.value;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

Gates and rules

GateBusinessClassHub
Publishable
users see it		 name + publishable location name + parent publishable always
Indexable
search engines see it		 name + coordinates + (phone or website) + description name + age range + description + (days or dates) + parent indexable ≥3 indexable listings + an intro

Missing values display as "Unknown" and rank a listing down. They never filter it out — a directory that hides incomplete listings is empty at launch, which is when it most needs to look populated.

The class gate is meant to be hard to pass

Dates measured 0% across every source class, so most classes will not be indexable at launch. That is the intended outcome: they stay visible to users inside the business listing, and stay out of the index until they are worth indexing. A class page carrying only a name is the thin, near-identical page that gets directory sites judged poorly.
