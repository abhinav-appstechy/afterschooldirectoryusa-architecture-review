This replaced an earlier design

The previous schema stored every value as a field-level claim with its own evidence sentence, assembled into listings by a resolver. It was designed against coverage measured over rendered HTML pages — dates 0%, age 37%.

Measuring the data endpoint instead gave a different world: dates 90%, age 100%, descriptions 98%. Classes arrive complete, so the model inverted — Python proposes whole classes, Laravel judges them, and the claims machinery was retired.

Detail lives in two companion pages: What Python does and What Laravel does. The reasoning behind the whole system is in the architecture review. The build plan is M2 — schema and seed.

The whole database

Orange is written by Python, petrol by Laravel, crimson is shared. The highlighted line is the seam: scraped_classes is the only thing Laravel reads from Python's side, and Python has no write grant on anything to the right of it.

Two conflicts found while reconciling the halves

1 · Two tables were both called pages

Python stores fetched page bodies; the CMS stores static pages like About and Privacy. Same name, same database, entirely different things. Renamed to fetched_pages and content_pages — caught on paper, which is the cheap place to catch it.

2 · sources is shared, not Python's

The two design pages disagreed. Resolved: Laravel writes the registry — an admin adds a source and sets its terms verdict, and only an admin may. Python updates operational columns only: health, last yield, next run. Column-level grants, so Python cannot change a verdict and Laravel does not fabricate health.

It is the one table both sides write, and the only one that needs a grant finer than the table.
