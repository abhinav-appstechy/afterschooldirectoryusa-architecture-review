Judging — the whole point

scraped_classes (new | changed) │ JudgeClass ├── confident ──► upsert business + venue + class ──► live └── unsure ──► review_item ──► a human decides ──► live
#Sends it to a human
1Missing fields — no age, no venue, no dates
2The venue will not resolve to coordinates
3Weak source — prose extraction rather than a clean endpoint
4It conflicts with a decision a human already made
5A suspicious change — price or age jumped on a live class
6Not obviously for kids — ages 7–99, or an adult class in a mixed catalogue

Everything else publishes without a person. At LA scale that is the difference between dozens of reviews and thousands.

Sources and verdicts

admin pastes a URL └─► source created, verdict: unknown nothing fetches └─► Laravel queues a terms-check run └─► Python proposes a verdict + the quoted clause └─► verdict: pending still nothing fetches └─► admin confirms or overrides

Adding a source is a paste. What you wait for is a confirmation click, not an engineering ticket. pending is visibly waiting, not silently dead.

Run now inserts a run with reason: admin — same queue, same gate, same politeness as the nightly run. It queues rather than scrapes, and the row shows queued → running → done · 42 classes. A double press is harmless: a partial unique index prevents two active runs for one source.

What 90% dates unlock

Endpoint sources carry real start and end dates, so Course + CourseInstance becomes genuinely emittable — a rich-result opportunity the earlier design had written off. Emit the instance only where dates exist; without them it is worse than omitting it.

Payments — Phase 3

Parents pay; businesses are listed free, so money never touches ranking. Cashier owns subscriptions; we add plans and plan_entitlements.

Stripe owns the price

amount_cents is a display cache synced by webhook and read-only in the admin. If an admin can edit a price locally, a parent is eventually billed an amount the page did not show them. Plans are retired, never deleted — old subscriptions still point at them.

Customers cancel themselves, running to the end of the paid period. An admin may cancel: audited, and the customer is emailed. No refund UI — refunds stay in Stripe.
